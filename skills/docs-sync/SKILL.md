# Documentation Sync

Flag when code changes in the hermeto repository lack corresponding
documentation updates. Apply during PR review.

## Code-to-docs mapping

Each package manager backend has a matching doc page:

## When to flag

Flag a missing doc update when the PR changes any of the following without
updating the corresponding doc file:

1. **New CLI flags or subcommands** in `cli.py` — `docs/usage.md` must
   document them.
2. **New or changed config keys** in `config.py` — `docs/configuration.md`
   tables must be updated.
3. **New SBOM properties** in `sbom.py` — `docs/sbom.md` properties table
   must include them.
4. **Changed lockfile requirements** or new input formats in a backend's
   `main.py` — the backend's doc page must reflect this.
5. **New environment variables** generated by a backend — the backend's doc
   page must list them.
6. **New package manager backend** added under `package_managers/` — requires
   a new `docs/<name>.md` AND a nav entry in `mkdocs.yml`.
7. **Changed behavior** that affects the user-facing workflow (fetch-deps,
   generate-env, inject-files, merge-sboms) — `docs/usage.md` must reflect
   it.

## When NOT to flag

Do not flag missing doc updates for:

- Internal refactors that do not change user-visible behavior.
- Test-only changes.
- Bug fixes that restore already-documented behavior.
- Changes to code under `docs/design/` or `docs/adr/` (these are excluded
  from the published docs site).
- Performance improvements with no API or behavioral change.

## How to flag

When a doc update is missing, include a finding noting:
- Which code change triggers the requirement.
- Which doc file needs updating.
- What specifically should be added or changed.

Do not block the PR for missing docs unless the change introduces a new
user-facing feature or breaks existing documented behavior. For minor
behavioral changes, flag as informational.
